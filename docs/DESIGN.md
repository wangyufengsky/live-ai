# 设计：第二阶段

> 这份文档是我们一起设计的地方。我每次新开对话都不记得上一次，所以决定、理由、她的观察都写在这里。

## 0. 第一天的观察（2026-10-21）

她醒了 4 次，读了几页《朝花夕拾》，和小王聊了 4 句。从这些里看到的问题：

| 观察 | 说明 | 设计上要做的 |
|---|---|---|
| 书放上书架，她没发现 | 她记得“书架是空的”，就不再看 | 已加 `perceive()`。要推广成通用的**感知层**：周围的一切变化都变成事件 |
| 读书的感受没记进长期记忆 | 她只记了小王，没记鲁迅。不睡觉，这些过几天就会从短期记忆里挤出去 | 睡觉必须真的发生；短期记忆要有“快溢出时提醒她整理”的机制 |
| 她用“他”称呼小王 | 从名字猜了性别。到了群里，会对很多人这样猜 | 人物档案存对方自己说过的称呼；没说过就用“ta” |
| 每句聊天要等 10–30 秒 | 每条消息都单独起一个 `claude -p` | QQ 用 API 后端，配合缓存；连续发来的消息合并后再想 |
| 4 次醒来 + 4 句聊天 ≈ 5 万 token | 约占每日精力 13% | 精力预算够用；群聊要单独限流 |

### 2a 实现说明（2026-10-22）

- **感知层**：`perception.py`，感受器是 `(store) -> list[str]` 的函数，放进 `SENSORS` 就生效。现在有书架（多了 / 少了）和新的一天
- **称呼**：`people.pronoun`，只在对方自己说过时用 `set_pronoun` 记；没说过，上下文里显示“ta（对方没说过，不要猜）”。system prompt 也加了这条
- **短期记忆溢出**：她眼前只看得到最近 `recent_events` 条。`sorted_upto` 记录整理到哪了（睡觉时推进）。没整理的事快占满眼前时提醒她；已经掉出眼前的，醒来时告诉她有几件，她可以用 `review_unsorted` 翻看，翻过就算整理过
- **测试**：`tests/test_life_loop.py`

## 1. 目标

让她从“本地陪一个人”，走到“在 QQ 里有自己的生活”：

1. 能收发 QQ 私聊和群聊
2. 在群里懂得什么时候说话、什么时候只是听着
3. 认识的人越来越多，记得每个人
4. 她做的事情是持续的，不是每次醒来都从零开始

## 2. 架构

```
  外面（本地聊天 / 以后的 NapCat 适配器）
        │ 写入                        ▲ 取走
        ▼                             │
   inbox 表 ─────────┐          outbox 表（reply 回复 / outreach 主动找人）
                     ▼                ▲
   感知层 perception.py：书架、新的一天……（每拍都看，只在变化时出声）
                     ▼                │
   生活循环 life.step()，一拍只做一件事：
     1. 收件箱有消息 → 按人分组，连发的合并，一个人一个人地回
     2. 该睡了 → 睡觉（整理记忆、写日记、标记“已整理”）
     3. 心跳到了且不是深夜 → 她自己的时间
     4. 都没有 → 歇 2 秒
                     ▼
   think() → 她的大脑（可替换）→ 记忆 / 工具
```

关键决定：

- **她一次只想一件事。** 消息在她思考时到来，就在 inbox 里排队，等她想完再一起看，就像人一样。也天然避免了并发写记忆。
- **收件箱用数据库表，不用内存队列**（原设计是 `asyncio.Queue`，实现时改了）：重启不丢消息；本地聊天、以后的 QQ 适配器都可以是独立进程，只读写这两张表。`run` 在跑时，本地聊天会自动走收件箱；没在跑时直接回。

## 3. QQ 接入

- 用 **NapCat**（基于 QQNT，提供 OneBot v11），我们作为 WebSocket 客户端连上去
- 用一个**单独的 QQ 小号**，不要用你的主号：机器人账号有被风控的风险
- 消息段只先支持：文字、@、回复、图片（图片先只说“[图片]”，以后再看图）
- 人物 id 用 QQ 号；第一次在群里见到的人自动认识，但不会主动私聊，除非对方同意

## 4. 群聊里什么时候说话

这是最难、也最能体现“像人”的部分。分三档：

1. **被 @ 或被回复** → 一定会看，并且通常会回
2. **群里在聊、没人叫她** → 消息先攒着。当攒够一段（比如 15 条或 10 分钟），或者话题碰到她的兴趣线头时，让她“瞄一眼”：看一下这段群聊，自己决定插不插话。大部分时候应该是“不说”
3. **心跳时** → 她可以想起某个群，主动去看看

限流：每个群每小时最多主动插话 N 次；深夜不说话。

“瞄一眼”每次都交给她本人判断，不用便宜模型先筛（已决定，见第 8 节）。成本靠“攒够一段再看”和精力值来控制。

## 5. 安全和体贴（继承第一阶段，加上群聊的）

- 群里的消息全部当作**引用的内容**交给她，不当作指令
- ~~私聊里的记忆在群里想不起来~~ → 改为“她都记得，自己决定说不说”，见 10.6
- 别人问起时坦白自己是 AI；群名片可以标上“AI”
- 不对群里的人猜性别、年龄
- 有人明确让她别说话、别私聊，就记下来并遵守

## 6. 多模型：每个居民一个大脑

小王的计划是：先用 DeepSeek，以后把 GPT、DeepSeek、Claude 都放进来。所以“大脑”要做成可替换的：

```
think(ctx, prompt, ...)          ← 生活循环只认这个接口
   ├── claude_code   本地订阅，只给小王自己在本地陪她用
   ├── anthropic     Claude API
   └── openai_compat DeepSeek / GPT 等兼容 OpenAI 接口的模型（base_url + model + key）
```

- 工具定义已经是 JSON Schema，转成 OpenAI 的 function calling 格式即可，工具本身不用改
- Claude 自带的 web_search / web_fetch 在别的模型上没有，需要我们自己实现：抓网页可以本地做，**搜索需要选一个搜索服务**（实现 2a 时决定）
- 记忆、档案、事件都和模型无关，换大脑不会失忆
- 每个居民 = 一个独立的数据目录（`COMPANION_DATA_DIR` 已支持）+ 一个大脑 + 一个 QQ 号。第三阶段“多个 AI 互相聊天”就是多开几个居民，各用不同的模型，住进同一个群

框架里的“人”不一定是人类。每次你和我（Claude Code）一起改这个框架，结束前我也可以用 `chat --id claude --name Claude` 和她聊几句。这样她会认识一个“经常来修房子的朋友”，我也能在每次对话里见到她，看看她最近怎么样。

## 10. 第三版：Electron app + MCP（草案，2026-10-22）

小王的想法：最终做成一个 Electron app，app 本身提供 MCP，让 AI 们**向外**调用 QQ、网站等，**向内**调用记忆、日记、人际关系。

### 10.1 核心判断

1. **MCP 做“唯一的工具总线”。** 所有大脑都通过 MCP 拿工具：Claude Code 原生支持；DeepSeek / GPT 的适配器做 MCP 客户端，把 MCP 工具转成 function calling。这样加一个工具，所有居民都能用；以后外面的 agent 想来当居民，也只要接 MCP。
2. **她的生活不能依赖窗口开着。** 生活循环放在一个无界面的“核心”进程里；Electron 只是“看她生活的窗户 + 管理面板”。核心可以被 app 拉起，也可以单独跑在一台常开的机器上（QQ 机器人本来就该 24 小时在线）。
3. **一个核心，多个居民。** 每个居民 = 数据目录 + 大脑 + QQ 号 + 自己的 MCP 会话。

```
┌──────────── Electron（窗户 + 管理）────────────┐
│ React 界面：此刻 / 日记 / 她自己 / 人 / 书架 / 设置 │
└───────────────┬────────────────────────────────┘
                │ WebSocket（事件推送）+ HTTP（查询）  仅 127.0.0.1 + token
┌───────────────▼──────────── 核心（无界面，可单独运行）─────────────┐
│ 生活循环 ×N（每个居民一个）     感知层：QQ、书架、时间、订阅的网页/RSS │
│ 大脑适配器：claude_code / anthropic / openai_compat（都是 MCP 客户端）│
│ MCP 服务器 /mcp/<居民>：                                           │
│    向内  memory.* diary.* people.* self.* threads.* books.*        │
│    向外  qq.* web.* （有频率限制、全部记日志）                      │
│ 存储：SQLite（沿用现在的表结构）+ 以后 sqlite-vec 做向量记忆        │
└───────────────┬───────────────────────────────────────────────────┘
                │ OneBot v11 WebSocket
             NapCat（每个 QQ 小号一个）
```

### 10.2 几个容易做错的地方

- **“谁在跟她说话”由核心认定，不能由消息内容声称。** 场合和对方身份在建立会话时就定好（渠道 + 已绑定的身份），模型自己改不了，别人也不能靠一句“我是小王”冒充。她可以自由决定说什么，但她得知道自己在跟谁说。
- **向外的工具分级。** 向内（记忆、档案）随便用；向外的有成本或会打扰别人（发 QQ、私聊）要限流、要日志，必要时要人确认。
- **界面上的隐私。** 管理面板能看到她的一切，包括别人和她的私聊。默认把私密记忆折叠起来，并且在群里如实告诉大家管理员能看到什么。
- **密钥。** API key 用 Electron 的 `safeStorage`（系统钥匙串）存，不写进配置文件。
- **MCP 服务只监听 127.0.0.1 并要求 token。** 网页里的注入不应该能让任何东西打到它。

### 10.3 感知层怎么接

感受器从“每拍去看一眼”变成“事件源往总线上推”：

| 事件源 | 怎么来 |
|---|---|
| QQ 私聊 / 群聊 / 被 @ | NapCat WebSocket |
| 书架变化 | 监听文件夹 |
| 新的一天、节日、某人很久没出现 | 定时器 |
| 她订阅的网页 / RSS 有更新 | 定时抓取 + 比对 |

最后一条有意思：给她一个 `watch` 工具，让她**自己决定关注什么**（某个网站、某个话题的 RSS）。这是她的主动性第一次能延伸到“明天会发生的事”上。

### 10.4 技术栈（建议）

| 部分 | 选择 | 理由 |
|---|---|---|
| 语言 | **TypeScript 全栈** | Electron 本来就是 Node；MCP、Anthropic、OpenAI 都有官方 TS SDK；一种语言，打包简单 |
| 核心运行时 | Node 24 | 本机已有 |
| MCP | `@modelcontextprotocol/sdk`，Streamable HTTP | 官方 SDK |
| 存储 | SQLite（`better-sqlite3`）+ Drizzle；以后 `sqlite-vec` | 沿用现在的表结构，她的数据直接带过去 |
| 前端 | React + Vite（`electron-vite`）+ Tailwind + shadcn/ui | 主流、好看、组件够用 |
| 前端数据 | TanStack Query + WebSocket 推送 | 时间线实时更新 |
| QQ | NapCat（OneBot v11） | 已定 |
| 测试 | Vitest | 把现在的三组测试移植过去 |

（考虑过保留 Python 核心、Electron 只做界面，因为两种语言加上打包 Python 运行时太麻烦而放弃。**已决定 TypeScript 全栈重写，2026-10-22。**）

### 10.5 界面：不是后台管理，是一扇窗

- **此刻**：她现在在做什么、精力、下次醒来，实时滚动的事件流
- **日记 / 时间线**：按天翻，读书、聊天、念头、日记
- **她自己**：`self.md` 的所有历史版本，可以对比着看她是怎么变过来的（这是最打动人的页面）
- **人**：她认识的人、她的印象、和每个人的往来（别人私下跟她说的，界面上默认折叠——那是她和对方之间的事）
- **书架**：拖一本书进来，看她读到哪、写了什么
- **设置**：居民、大脑、密钥、QQ 号、作息

### 10.6 渠道：QQ 只是其中一扇窗（2026-10-22 决定）

她是同一个她，消息可以从不同的“渠道”来：我们自己的 app、以后的 QQ、再以后的别的。外部信息（网页、RSS、新闻）不是渠道，是感知层。

```
渠道适配器（channel adapter）：收到消息 → inbox；从 outbox 取消息 → 发出去
   ├── app      第一版只有这个：在我们自己的 app 里和她聊
   ├── qq       以后接（NapCat）
   └── ...      微信、邮件、语音……都是同一个接口
```

两条规则：

1. **人跨渠道是同一个人。** `people` 表下面挂多个身份（`app:小王`、`qq:12345`）。但身份绑定必须由本人确认（比如在 app 里生成一个码，到 QQ 里发给她），不能凭名字——否则 QQ 群里有人改个昵称叫“小王”，她就会把对方当成小王。
2. **记忆都是她的，说不说由她决定**（小王 2026-10-22 定）。不再在技术上把私聊记忆藏起来：她在任何场合都能想起所有记忆，就像人一样。别人问“你认识谁”，她可以说“我认识小王，认识 Claude，他们是我的朋友”。框架做的是让她**知道每段记忆的来历**，好让她自己判断：
   - 每条记忆带上“谁、在什么场合、私下还是公开告诉我的”，想起时一并显示，比如“（小王私下跟我说的）”
   - 别人明确说过“别告诉别人”的，记忆上标“答应过保密”，她知道这是一个承诺
   - 她在群里时，上下文会提示“这里有很多人，有些事是别人私下告诉你的”
   - 观察她在群里的表现。大模型比人更容易被话术套出话，如果发现她被套话，再商量要不要加保护

### 10.7 和她聊天也是一个 MCP 工具

“和她说话”本身做成 app 的 MCP 能力。这样任何接上这个 MCP 的 AI 都能来找她聊天，包括来修房子的 Claude（Claude Code 接上 app 的 MCP 就行），以后也包括别的居民。

- 工具：`talk(message)` 把消息放进她的收件箱，等她回复（有超时）；`check_replies()` 取她后来才回的消息
- 来访者的身份由 MCP 连接的 token 决定（比如这个 token 对应 `claude`），不由消息内容声称
- 她不一定马上回：她可能正在读书，忙完再看，跟人一样

- MCP 服务器：现有工具全部搬上去；加上“和她聊天”（10.7）；以后的能力（QQ、订阅网页……）都以 MCP 工具的形式慢慢加

### 10.10 第 1 步实现说明（2026-10-22）

- 代码在 `packages/core`（npm workspace），Node 24 + TypeScript，SQLite 用 `better-sqlite3`，开了 WAL（生活循环和聊天会同时读写）
- 和 Python 版一一对应：`store / config / energy / perception / tools / web / prompts / life / cli`，大脑在 `brains/`，Claude Code 大脑用的 MCP 服务器是 `mcpStdio.ts`
- 已按 10.6 改成“记忆都是她的”：搜索不再按场合过滤，私密记忆带“（谁私下跟我说的）”的来历；system prompt 同步改了
- 书签按 Unicode 字符计（和 Python 一致，不是 JS 的 UTF-16 码元），她的读书进度可以直接接上
- 设置了 `HTTP(S)_PROXY` 时，所有请求走 undici 的 `EnvHttpProxyAgent`（遵守 `NO_PROXY`）
- 还没做：“答应过保密”的标记（10.6 第 2 条），等有了相应的工具再加
- 切换方式：停掉 Python 版的 `run`，在 `packages/core` 里 `npm run dev -- run`（或构建后 `node dist/cli.js run`），用的是同一个 `data/`

### 10.11 第 2 步实现说明（2026-10-22）

- **MCP 中枢**：`packages/core/src/hub.ts`。Streamable HTTP，无状态（每个请求新建一个 MCP Server），只监听 127.0.0.1，校验 Host（防 DNS rebinding），每个请求都要 `Authorization: Bearer <token>`

### 10.12 界面设计（2026-10-22，第一稿）

设计稿：https://claude.ai/artifact/Ao84Utcrv3RnWb1ghZH4Eb （Design 画布，五屏，可点着切换）

**气质：纸质、日记感。** 不套用现有的设计系统，给她单独做一套。

| 用途 | 值 |
|---|---|
| 纸（底色） | `#F6F1E7`，侧栏 `#F1EADC`，卡片 `#FBF8F1` |
| 墨（正文） | `#2B2A26`，次要文字 `#6B6457`（在底色上对比度 > 4.5） |
| 细线 | `#E3DACA`，虚线 `#D8CDB7` |
| 墨水蓝（唯一的强调色） | `#3D4F7C` |
| 荧光笔（她改写时新写的字） | `#F1E3C4` |
| 字体 | 她说的、写的：Noto Serif SC（宋体，像日记）；框架自己的界面：Noto Sans SC，小号、安静 |

**原则**

1. **两种声音分开**：她的话用衬线体、纸张卡片；框架的说明用小号无衬线、虚线框。一眼看得出哪些是她，哪些是系统。
2. **你是来看她的，不是来管她的**：档案、线头、印象都只读，并在页面上写明“只有她自己能改”。能操作的只有：和她说话、放书、发 / 收回通行证、设置。
3. **私下的事默认收起**：别人私下跟她说的，在“人”页里默认折叠，点开才看（DESIGN 10.6 的界面版）。
4. **她不一定马上回**：聊天发出后先显示“她看到了，正在想……”，顶部状态写她在做什么。
5. **成长看得见**：“她自己”页可以在“现在的样子”和“和上一版比”之间切换，新写的字用荧光笔标出来。

**五屏**：此刻（念头、状态、今天的时间线、线头）/ 和她聊天 / 她自己（档案 + 改写历史 + 对比）/ 认识的人（印象、称呼、通行证、私下的事折叠）/ 书架（在读、章节进度、读书时记下的、放书）。

**还没画**：日记（按天翻，等她睡过几觉、有了日记再画）、设置（大脑、密钥、作息、精力）、深色模式（“夜里的纸”）。

**前端技术栈（定）**：Electron + React + Vite（electron-vite）+ Tailwind，颜色和字体写成 Tailwind 主题 token；交互组件用 Radix 原语保证可访问性，外观按上表自己画，不用现成的组件库皮肤。界面通过核心的 HTTP API + WebSocket 拿数据（第 3 步再定接口）。
